# KSeF (Krajowy System e-Faktur)

## What this is
Integration with Poland's national e-invoice system (KSeF). Supports sending FA(3) XML invoices, polling submission status, downloading UPO receipts, and receiving incoming invoices. Implements a strategy pattern with two adapters: wFirma proxy and direct KSeF API.

## Entry points
- `packages/api/src/services/ksef/ksef.service.ts` — `KSeFService`: main facade routing requests to the active adapter
- `packages/api/src/services/ksef/adapters/wfirma-adapter.ts` — routes KSeF operations through wFirma API
- `packages/api/src/services/ksef/adapters/direct-adapter.ts` — calls KSeF API directly (requires MF token)
- `packages/api/src/services/ksef/xml-generator.ts` — builds FA(3) XML from invoice data
- `packages/api/src/services/ksef/status-poller.service.ts` — background polling for `pending`/`sending` invoices
- `packages/api/src/services/ksef/contractor.service.ts` — KSeF-specific contractor lookup and creation
- `packages/api/src/routes/ksef.routes.ts` — `/api/ksef/*` REST endpoints
- `packages/web/src/app/ksef/` — frontend pages (invoice list, settings, guides)

## Key concepts
- **Adapter pattern** — `IKSeFAdapter` interface implemented by both `WFirmaKSeFAdapter` and `DirectKSeFAdapter`; `KSeFUserConfig` in the database records which adapter a user has chosen.
- **FA(3) XML** — Polish e-invoice XML format (schema in `fa3-schema.xsd` at repo root); generated by `xml-generator.ts`.
- **Status lifecycle** — `pending → sending → sent → accepted/rejected → completed`; tracked in `KSeFInvoice` Prisma model.
- **UPO** — Urzędowe Poświadczenie Odbioru (official receipt); downloaded after acceptance and stored.
- **Auto-send** — `auto-send.service.ts` periodically checks for new accepted wFirma invoices and sends them to KSeF.
- **Deduplication** — `KSeFInvoice` has a unique constraint on `externalId` to prevent double submission.
